# E002-S01-003: Verify an archive without touching a site


**Implements:** FR-3


As an operator,
I want to check that an archive is still good,
So that I find out before a restore rather than during one.

**Acceptance Criteria:**

**Given** an Archive produced by this tool
**When** verification runs
**Then** it reports pass or fail and makes no write outside its own temporary workspace
**And** a truncated or corrupted Archive fails
**And** a Manifest declaring a Dump that is absent is a verification failure, not a restore-time surprise
**And** the result carries `integrity` (`VERIFIED` or `STRUCTURAL_ONLY`), not only pass or fail, so a v0 Archive passes as `STRUCTURAL_ONLY` (AD-23)

## Business acceptance criteria

### Outcome

`wpbackup2 verify --archive <target>` (and the library `verify` entry point) reads an Archive and reports one of three results: **pass with `integrity: VERIFIED`** (a v1 Archive whose Manifest parses and whose every member checksum matches the bytes as stored), **pass with `integrity: STRUCTURAL_ONLY`** (a v0 Archive — no Manifest — whose expected members `database.sql` and `wp-root/` are present and whose tar stream reads to the end), or **fail** naming the first reason. It writes nothing outside its own private workspace and touches no Site. The same verifier is the one E002-S01-001 runs before publishing and the one Epic 3 runs before any destructive step. A reviewer can tell it happened by corrupting one byte of a v1 Archive and seeing a fail that names the member.

### Non-goals

- Running verification automatically before a destructive restore step — moved to Epic 3 story 3.1 (AG-29); this story ships the verifier that story calls.
- Restoring or extracting an Archive onto a Site — Epic 3. (The extraction *function* lands here because `adapters/tar` is Epic 2's; see Interface contracts.)
- Decrypting `age`-encrypted members — Epic 4 (story 4.3). An Archive whose Manifest marks a member `encrypted: true` is checksum-verified over its ciphertext (checksums are over bytes as stored), so verification needs no key.
- The committed v0 fixture Archives and their tests — Epic 4 owns them (Epic List ownership note). This story writes the v0 classifier branch and tests it against a v0-shaped tar built inside the test.
- Remote Storage Targets — v1.1.

## Technical acceptance criteria

### Interface contracts

Files added or changed under `src/l3io/wp/backup/`, following the conventions E002-S01-001 records (module docstring naming the AD, `from __future__ import annotations`, `__all__`, no new `__init__.py` above the leaf, pure layers inside `tools/check_purity.py` and the import-linter contracts).

- **`ports/archive.py` — `ArchiveProbe` (AD-23, AG-7).** A query port: `ArchiveProbe.member_index(source: StorageTarget) -> MemberIndex`, where frozen `MemberIndex(names: tuple[str, ...], first_member: str | None, manifest_text: str | None, readable_to_end: bool, gzip: bool)`. It returns raw facts only; it never decides a format. A second query, `ArchiveProbe.member_digests(source) -> Mapping[str, MemberDigest(size: int, sha256: str)]`, streams every member once. Neither accepts nor returns `bytes` (AD-21).
- **`domain/archive_format.py` — the pure classifier and the normalized view (AD-23, AG-7; decision of the Epic List ownership note: this module is Epic 2's alone, v0 branch included).** `classify(index: MemberIndex) -> ArchiveView`. A first member named `manifest.json` means v1 and its `format_version` governs (an unsupported version raises `UnsupportedFormatVersionError(found=...)`); no Manifest plus members `database.sql` and `wp-root/` means v0; anything else raises `UnrecognisedArchiveError(found=<first few member names>)`. Detection never looks at a filename or extension. `ArchiveView` is frozen and carries `format_version: int | None` (None for v0), `members: tuple[ViewMember, ...]` with **synthesized roles** (v0's `database.sql` → `dump`, `wp-root/…` → `site-root`), `checksum: str | None` per member (None for v0), `dump_present: bool`, `config_path: str | None` (None for v0, triage E-17), and `integrity: Integrity` where `class Integrity(StrEnum): VERIFIED = "VERIFIED"; STRUCTURAL_ONLY = "STRUCTURAL_ONLY"`. **No module outside `domain/archive_format` branches on format version** — enforced by a contract test (see Testability).
- **`MemberIndex`, `MemberDigest` and `ArchiveView` are domain types** (in `domain/archive_format.py`) so the port can return them without `domain/` importing `ports/` (AD-1).
- **Supported format set (AD-6, triage E-18).** The supported set is **the set of fixture Archives committed under `tests/fixtures/archives/`**, not a declared interval. This story commits `tests/fixtures/archives/v1/minimal.tar.gz` (written by E002-S01-001's writer from `tests/data/wp-config.php` plus a few-kilobyte site tree and a tiny Dump, generated by a script under `tests/fixtures/archives/` that is checked in beside it) and a contract test asserts every `format_version` value the classifier accepts has at least one fixture and every fixture classifies. `v0/` is a named member of the set whose fixtures Epic 4 commits; until they exist the test records v0 as accepted-without-fixture and says so in its failure text rather than passing silently.
- **`core/verify.py` — pure comparison.** `verify(view: ArchiveView, digests: Mapping[str, MemberDigest]) -> VerificationResult`, frozen `VerificationResult(passed: bool, integrity: Integrity, format_version: int | None, failures: tuple[VerificationFailure, ...])`, `VerificationFailure(member: str | None, reason: VerificationReason)`, `class VerificationReason(StrEnum)`: `CHECKSUM_MISMATCH`, `SIZE_MISMATCH`, `MEMBER_MISSING`, `UNDECLARED_MEMBER`, `DUMP_DECLARED_ABSENT`, `TRUNCATED`, `UNREADABLE`, `UNRECOGNISED_FORMAT`, `UNSUPPORTED_VERSION`, `UNSAFE_MEMBER_PATH`. `integrity` is never omitted: a v1 pass is `VERIFIED`, a v0 pass is `STRUCTURAL_ONLY`; a v1 Archive cannot pass as `STRUCTURAL_ONLY` (AG-17).
- **`adapters/tar.py` — `TarArchiveProbe` and the one extraction function.** `TarArchiveProbe` implements `ArchiveProbe` with stdlib `tarfile` in stream mode (`r|*`, which handles both gzip and plain tar), reading each member in fixed-size chunks into `hashlib.sha256`. It also lands **`extract_archive(source, destination: Path, view: ArchiveView, *, roles: frozenset[MemberRole]) -> None`**, the single extraction function AD-11 requires for every restore path: `filter="data"` passed explicitly when `hasattr(tarfile, "data_filter")`, refusal (never `fully_trusted`) where it is absent, and containment re-checked against `destination` after role-prefix stripping. Epic 3 cannot add it because `adapters/tar` is Epic 2's; it is unused by `verify` itself.
- **Verifier entry point for the publish gate.** `adapters/tar.py::verify_archive(path: Path) -> VerificationResult` composes probe + classify + `core/verify`; E002-S01-001's `LocalArchiveStore` is bound to a wrapper that raises `VerificationFailedError(result)` when `passed` is False.
- **CLI.** `cli/parser.py` gains a third subcommand, `verify`, taking `--archive` (required). This is an addition, which AD-22 permits; `backup` and `restore` are unchanged. `cli/verify.py::run_verify(args) -> int` returns 0 on pass and the backup-only verification-failure code from E002-S02-006 on fail (1 until that story lands). The human output names `integrity`; a v0 pass prints that integrity was not checked because v0 carries no checksums.
- **Errors.** `VerificationFailedError(BackupError)` carries `result: VerificationResult`; `UnrecognisedArchiveError`, `UnsupportedFormatVersionError` subclass `BackupError` in `domain/errors.py`.

### Error and edge case handling

- Truncated gzip or tar stream (cut at any byte offset, including inside the Manifest): fail, `TRUNCATED`; never an unhandled `EOFError`/`tarfile.ReadError` reaching the caller.
- One byte flipped inside a member: fail, `CHECKSUM_MISMATCH` naming that member.
- Manifest declares `dump_present: true` and no `dump`-role member exists: fail, `DUMP_DECLARED_ABSENT` (FR-3).
- A member present in the tar but absent from the Manifest index, or the reverse: fail, `UNDECLARED_MEMBER` / `MEMBER_MISSING`.
- `manifest.json` present but not the first member: not v1 — fail `UNRECOGNISED_FORMAT`; a v0 shape with a stray `manifest.json` later in the stream is also `UNRECOGNISED_FORMAT`, not silently v0.
- `manifest.json` not valid JSON, or missing `format_version`: fail `UNREADABLE`; a `format_version` with no fixture in the supported set: fail `UNSUPPORTED_VERSION` naming the version found.
- A member path that is absolute, contains `..` or escapes its role prefix: fail `UNSAFE_MEMBER_PATH` during verification, before any caller extracts.
- A v0 Archive missing `wp-root/` or `database.sql`: fail `MEMBER_MISSING` (structural check), never `STRUCTURAL_ONLY` pass.
- Empty file, non-tar file, a `.zip`: fail `UNRECOGNISED_FORMAT` naming what was found.
- Archive path does not exist or is unreadable: `ArchiveNotFoundError(BackupError)` with `raise ... from` the `OSError` — not a bare `FileNotFoundError` (AD-14's named example).
- A non-`file:` Storage Target: `UnsupportedStorageSchemeError` from E002-S01-001's grammar.

### Security considerations

- An Archive is untrusted input (AD-11, NFR-5): the probe reads headers and streams member bodies into a hash; it never writes a member to disk, never follows a member's link target, and never calls `extractall`. Verification therefore writes nothing at all except, if it needs one, the Run workspace — asserted by a test that snapshots the parent directory, the Archive's directory and the Site Root before and after.
- Member names from the Archive reach logs and error messages only after `repr()`-style escaping, so a crafted name cannot inject log lines or terminal escapes.
- Manifest JSON is parsed with stdlib `json.loads`; its size is capped (a Manifest larger than a stated constant, e.g. 16 MiB, fails `UNREADABLE`) so a crafted Archive cannot exhaust memory through the one member read whole.
- `extract_archive` refuses on an interpreter without `tarfile.data_filter` rather than extracting unfiltered.

### Testability approach

- `tests/unit/domain/test_classifier.py`: v1 index → v1 view with `VERIFIED`-capable members; v0 index (built in the test) → `STRUCTURAL_ONLY`, roles synthesized, `config_path is None`; `manifest.json` not first → `UnrecognisedArchiveError`; unknown shapes rejected. Pure — `MemberIndex` values built by hand, no tar.
- `tests/unit/core/test_verify.py`: one case per `VerificationReason`, parametrised from `list(VerificationReason)` with a case table keyed by the enum, and a test that fails if a reason has no case (scope from the enum).
- `tests/adapters/test_tar_probe.py`: truncation at every offset in a small Archive (a loop over `range(len(data))`, not a few chosen offsets); single-byte flips per member; v0-shaped tar built with `tarfile` in-test.
- `tests/contracts/test_extraction.py`: its tripwire is **replaced**, as its docstring directs, with tests driving `extract_archive`: a `../escape` member refused; a symlink escaping the destination refused; containment re-checked after role-prefix stripping; the refusal path taken when `data_filter` is monkeypatched absent. Run on every Python in the CI matrix (the existing `AD-11 extraction containment` CI step).
- `tests/contracts/test_version_branching.py`: AST walk over every module under `src/l3io/wp/backup/` **except** `domain/archive_format.py`, failing on any `if`/`while` test, comparison, conditional expression or `match` subject that references a name or attribute `format_version` (reading it to log or display it is allowed) — scope derived by walking the package, with a scope assertion that the walk found modules.
- `tests/contracts/test_supported_formats.py`: the fixture-derived supported set, as above.
- `tests/integration/test_verify_cli.py` (`@pytest.mark.integration` only where a live database is needed to build the Archive; otherwise the committed fixture is used, unmarked): `wpbackup2 verify` exit code and output for a good, a corrupted and a v0-shaped Archive; and the end-to-end check that E002-S01-001's backup publishes only after this verifier passes (a verifier forced to fail leaves no final name).
- Workspace-only writes asserted as described under Security.

### Existing-library check

stdlib `tarfile` (stream mode, `data_filter`), `gzip` via `tarfile`, `hashlib` and `json` cover the probe, the checksums and the Manifest; AD-23 forbids hand-written tar, gzip or JSON parsing, and none is written. Format detection is a classification over the member index, not a parser. No third-party dependency is added.
