# E002-S01-001: Produce an archive of a site's files and database


**Implements:** FR-1


As an operator,
I want one command to capture my whole WordPress site into a single file,
So that I have something to restore from.

**Acceptance Criteria:**

**Given** a Site Root containing a readable `wp-config.php`
**When** a backup runs naming only that directory
**Then** one Archive is produced containing a Dump, the Site Root tree and a Manifest
**And** with no Credential Provider given, the database credentials are resolved from that `wp-config.php` (FR-1)
**And** the Dump is produced by `l3io-wp-database`'s `dump`; this package invokes no MySQL client tool (ADR-0015)
**And** the Site is byte-identical afterwards — file mtimes, database contents and `wp-config.php` unchanged
**And** the Archive becomes visible at its destination only once complete and verifiable (NFR-2)
**And** no step reads the whole Archive or Dump into memory (AD-21)

## Business acceptance criteria

### Outcome

`wpbackup2 backup --wp-dir <Site Root>` (and the same call through the library entry point) produces exactly one v1 Archive — a gzipped tar whose first member is `manifest.json`, followed by a `dump`-role member and the `site-root`-role tree — at the Storage Target, resolving database credentials from that Site Root's `wp-config.php` when no Credential Provider is given. A reviewer can tell it happened by listing the Archive's members, reading its Manifest, and confirming the Site, the database and `wp-config.php` are byte-identical before and after. A failed backup leaves nothing at the final Archive name.

### Non-goals

- Backup Scope selection (`--mode files|db`) — story E002-S01-002. This story always writes Backup Scope `all`.
- The `verify` command, the `ArchiveProbe` port, the classifier and the `ArchiveView` — story E002-S01-003. This story's publish gate takes the verifier as an injected callable; E002-S01-003 binds its `verify_archive` into that gate. Order: this story lands first (it defines the format S01-003 reads), S01-003 second, and the end-to-end "published only after it verifies" integration test is S01-003's.
- Encryption: every member is written with `encrypted: false`. `age` recipients are Epic 4 (story 4.3); passphrase encryption waits for `l3io-wp-database` 0.2.0.
- Exclusions (FR-5) — Epic 4, `core/exclusions`.
- Remote Storage Target backends (S3, SFTP, rsync) — v1.1. Only `file:` targets are accepted.
- Run ID, structured per-phase log fields and the logging configuration — E002-S02-005; exit-code numbers — E002-S02-006; Dry Run — E002-S02-007; the Site Lock — E002-S02-008. Each of those stories wires itself into the backup composition root this story creates.
- Credential Providers other than `wp-config.php` (explicit, environment, AWS) — Epic 5 (story 5.1).

## Technical acceptance criteria

### Interface contracts

Files added (all under `src/l3io/wp/backup/`). Sibling conventions, read from the existing tree: every module opens with `from __future__ import annotations`, carries a module docstring naming the AD it implements, and declares `__all__` (see `domain/flag_map.py`, `cli/parser.py`); no new `__init__.py` anywhere above `l3io/wp/backup/` (AD-27, `tests/contracts/test_namespace_layout.py`); `domain/` and `core/` stay inside `tools/check_purity.py` and the three `[tool.importlinter]` contracts unchanged — no exemption is added to either.

- **`domain/site.py` — the Site Descriptor (AD-3, AG-8).** `@dataclass(frozen=True, slots=True) class SiteDescriptor` with fields `site_root: PurePosixPath` (absolute, already canonicalised by the caller), `db_host: str`, `db_port: int`, `db_name: str`, `table_prefix: str`, `site_url: str | None`, `home_url: str | None`, `credential_source: str` (the provider's label, never a secret). A Glossary field with no source in `wp-config.php` is `None`, never defaulted. No setters and no `@property` with a setter; `dataclasses.replace` is the only way to derive a changed value. Invalid or incomplete values (relative `site_root`, empty `db_host`/`db_name`, port outside 1–65535) raise `InvalidSiteDescriptorError` from `__post_init__` — at construction, not at use (FR-22). The descriptor holds no credential object: the provider itself travels with the bound adapters, because `domain/` may not import the provider's Protocol from `ports/` (AD-1).
- **One construction site.** `adapters/database.py::site_descriptor_from_wp_config(site_root: Path) -> tuple[SiteDescriptor, CredentialSource]` is the only code that reads `wp-config.php`, through `l3io.wp.database.WpConfigFile(path)` (v0.1.0: `.connection()`, `.resolve()`, `.table_prefix`, `.source`). `host:port` is split exactly once, by database's `Connection.from_db_host`; this package contains no second splitter. Nothing below the composition root opens `wp-config.php` again (AD-3).
- **`domain/archive_format.py` — the one owned archive contract (AD-6, AG-6).** Declares `FORMAT_VERSION: Final = 1`; `MANIFEST_MEMBER: Final = "manifest.json"`; `class MemberRole(StrEnum): DUMP = "dump"; SITE_ROOT = "site-root"; CONFIG = "config"`; `member_path(role: MemberRole, relative: str) -> str`, which returns a role-prefixed path and raises `UnsafeMemberPathError` for an absolute path, a `..` segment, a NUL, or a backslash; frozen `ManifestMember(path, role, size: int, sha256: str, encrypted: bool)`; frozen `Manifest(format_version: int, created_at: str, backup_scope: str, source: dict[str, str | int | None], members: tuple[ManifestMember, ...], dump_present: bool, dump_sha256: str | None)`; `manifest_to_json(m) -> str` and `manifest_from_json(text) -> Manifest` using stdlib `json`, where reads ignore unknown keys. `created_at` is UTC ISO-8601 with an explicit `+00:00` offset, supplied by the caller (the clock is not read in `domain/`). `source` is the descriptor projected without `credential_source`'s provider object and with no credential value. The Manifest carries **no key material and no KDF parameters** (ADR-0014 overrides FR-4's "KDF parameters, salt"). No other module defines a member name, the Manifest key set or the version number — a test greps `src/` for the literals `"manifest.json"`, `"dump/"` and `"site-root/"` outside this module and fails on any hit.
- **`domain/storage_target.py` — the Storage Target grammar (AG-27).** `parse_storage_target(text: str) -> StorageTarget`, frozen `StorageTarget(scheme: Literal["file"], path: PurePosixPath)`. `file:///abs/x.tar.gz` and a bare path (relative paths resolved by the caller before parsing) both yield `scheme="file"`; any other scheme (`s3://`, `sftp://`, `http://`) raises `UnsupportedStorageSchemeError(scheme=...)`. URL splitting uses stdlib `urllib.parse.urlsplit` in the adapter that calls this, or the parser receives an already-split value — `domain/` imports no `urllib` (it is on the import-linter forbidden list); whichever, no regex URL parser is written. With no `--archive`, the target defaults to the legacy name `wpbackup2-<db_name>-<YYYYmmddHHMMSS>.tar.gz` in the current directory (preserved behaviour, timestamp UTC).
- **`domain/errors.py` — the package exception hierarchy (AD-14, AG-19).** One base, `BackupError(Exception)`, carrying structured fields as attributes (never only a message). This story introduces `InvalidSiteDescriptorError`, `UnsafeMemberPathError`, `UnsupportedStorageSchemeError`, `CredentialsError`, `DatabaseUnreachableError`, `DumpFailedError`, `ArchiveWriteError` and `MissingExtraError(extra: str)`. Every exception from `l3io.wp.database`, `tarfile`, `OSError` or `json` reaching a public boundary is caught in the adapter and re-raised as one of these with `raise ... from`. Later stories add subclasses here; none defines a second base.
- **`core/backup.py` — the plan (AD-1).** `build_backup_plan(site: SiteDescriptor, scope: BackupScope, target: StorageTarget) -> BackupPlan`, pure; `BackupPlan.steps` is an ordered tuple of `BackupStep` enum values (`DUMP`, `COLLECT_SITE_ROOT`, `WRITE_ARCHIVE`, `VERIFY`, `PUBLISH`). The core never receives a filesystem path it did not get from its arguments (AD-12). `BackupScope` is the domain enum E002-S01-002 defines; until that story lands, this story defines `BackupScope.ALL` only in `domain/backup_scope.py` and S01-002 completes the set.
- **`ports/archive.py` and `ports/database.py` — split into queries and commands from the first line (AD-4; the mechanism is carried by E002-S02-007, AG-12).** `ArchiveStoreQuery.exists(target) -> bool`; `ArchiveStoreCommand.stage(target) -> StagedArchive` where `StagedArchive.stream: IO[bytes]`, `.publish() -> None`, `.discard() -> None`; `DatabaseQuery.check_dump(site) -> DumpReadiness`; `DatabaseCommand.dump_to(site, destination: Path) -> DumpResult(bytes: int, duration_ms: float)`. **No port that moves Archive or Dump bytes accepts or returns `bytes`**; they take or return `IO[bytes]` or a `Path` (AD-21, AG-13).
- **`adapters/database.py` — the one place that calls `l3io-wp-database` (ADR-0015).** Calls `l3io.wp.database.dump(connection, credentials, to, *, recipients=None, options=())` (verified against tag `v0.1.0`, `transfer.py` L476) with `to` a path inside the Run workspace, which database writes atomically at mode `0600`. `l3io.wp.database` is the optional extra `database` in `pyproject.toml`, so it is imported **inside the functions that use it**, never at module scope; absence raises `MissingExtraError(extra="database")` (AD-8). This package invokes no MySQL client tool and writes no option file (`tests/contracts/test_no_mysql_client.py` stays green).
- **`adapters/tar.py` — the writer.** `write_archive(out: IO[bytes], manifest: Manifest, members: Iterable[ArchiveMemberSource]) -> None`, gzip-compressed tar (`tarfile.open(fileobj=out, mode="w|gz")`, triage E-16), `manifest.json` written as the **first** member, then the `dump/` member, then `site-root/…` members in a deterministic (sorted) order. Checksums are SHA-256 (stdlib `hashlib`) over each member's bytes **as stored**. Because the Manifest precedes the members, the adapter either hashes in a first streaming pass and re-hashes during the write, or stages members in the workspace; whichever, a member whose bytes change between hashing and writing fails the backup — it is never published with a stale checksum.
- **`adapters/store.py` — `LocalArchiveStore` (AD-20, AG-21).** Implements both `ArchiveStore` halves. `stage()` opens a temporary name **in the destination directory** (same filesystem, so the rename is atomic), created with `O_EXCL` and mode `0600`; `publish()` first calls the verifier injected at construction (`verify: Callable[[Path], None]`, raising a `BackupError` subclass on failure; bound by the composition root — E002-S01-003's verifier once it lands) against the staged file and only on a pass calls `os.replace` onto the final name; there is no constructor default for `verify`, so a store that skips verification cannot be built by omission; `discard()` removes the temporary file. Any exception between `stage()` and `publish()` calls `discard()` in a `finally`. An existing file at the final name is refused, not overwritten.
- **`adapters/workspace.py` — the per-Run private workspace (AD-12, AG-18).** `run_workspace(parent: Path | None) -> ContextManager[Path]` creates the directory with `tempfile.mkdtemp(prefix="l3io-wp-backup-")` (mode `0700` by construction), yields it, and removes it with `shutil.rmtree` in a `finally` on success **and** failure. `parent` overrides only *where* it is created. The Dump file lives only inside it, under a per-Run name — never `/tmp/database.sql`. E002-S02-005 folds this workspace into the Run Context; this story's composition root uses it directly. (This module is outside the listed `adapters/{tar,database,store,lock}` set in the Epic List; no other epic claims it.)
- **`cli/` — the backup composition root.** `cli/parser.py` gains `--wp-dir` (required) and `--archive` on the shared parent parser, spelled exactly as v0.2.21 (AD-22); `cli/__init__.py::main` dispatches `backup` to a `cli/backup.py::run_backup(args) -> int` that canonicalises `--wp-dir` with `Path.resolve(strict=True)`, builds the descriptor, workspace, plan and adapter set, executes the plan, and returns 0 on success and a non-zero value on every failure. The numeric values come from E002-S02-006's enum once it lands; until then failures return 1.

**Added 2026-10-20 (gap pass: contracts Epics 3 and 4 found missing; decision 1 of 2026-10-20 — Epic 2 provides them).** Every key below is additive and optional, so `FORMAT_VERSION` stays `1` and a reader built before them still reads an Archive written after them (reads ignore unknown keys).

- **`Manifest.origin: ManifestOrigin | None` (FR-6, AD-6; E003-S02-003).** Frozen `ManifestOrigin(kind: OriginKind, restore_mode: str, run_id: str)` with `class OriginKind(StrEnum): SAFETY_SNAPSHOT = "safety_snapshot"` in `domain/archive_format.py`. `restore_mode` is the `RestoreMode` value string (E002-S02-006's enum), carried as `str` so `archive_format` does not import the restore types. Serialised as the `origin` key `{"kind", "restore_mode", "run_id"}` only when not `None`; an ordinary backup's Manifest has no `origin` key at all, so its bytes are unchanged by this addition.
- **`Manifest.exclusions: ManifestExclusions | None` (FR-5, AD-6; E004-S01-001).** Frozen `ManifestExclusions(source: str, patterns: tuple[str, ...], excluded: tuple[ExcludedEntry, ...])`, serialised as `{"source", "patterns", "excluded": [{"path", "pattern", "is_dir"}, ...]}`. `ExcludedEntry(path: str, pattern: str, is_dir: bool)` and the policy's return value `ExclusionDecision(excluded: bool, pattern: str | None, protected: bool)` are defined in a new pure module **`domain/exclusion.py`**, because both `core/exclusions` (Epic 4, which may import only `domain/`) and `adapters/tar` must name them; Epic 4 imports them from there and defines neither. `source` is one of `"default"`, `"custom"`, `"none"`. Written whenever a `site-root` member set was collected (the key is present with `source="none"` and empty tuples when nothing is excluded), absent for a `database`-scope Archive.
- **The traversal hook (FR-5; E004-S01-001).** `ports/exclusion.py::ExclusionPolicy(Protocol)`: `decide(relative: PurePosixPath, *, is_dir: bool) -> ExclusionDecision` (a pure query, on E002-S02-007's single-role allowance). `adapters/tar.py`'s Site Root traversal (`collect_site_root(site_root: Path, policy: ExclusionPolicy) -> SiteRootCollection` with `.members` and `.excluded: tuple[ExcludedEntry, ...]`) calls `decide` once per entry **before** descending; an excluded directory is pruned without being listed, and only the top-most pruned path is recorded. `adapters/tar.py::INCLUDE_EVERYTHING` is the policy bound when no exclusion is configured (`decide` always returns `excluded=False`); `wp-config.php` at the Site Root is never excluded by any policy — the traversal re-checks `decision.protected`/the path itself and ignores an `excluded=True` for it, so a policy defect cannot drop the config.
- **Encryption seam: the cipher port, the plan step and the writer (FR-4, ADR-0014; E004-S01-003 items 1–3).** `build_backup_plan(site, scope, target, *, encrypted: bool)` — `encrypted` is required (no default, so no caller encrypts or skips encryption by omission); when `True` the plan inserts `BackupStep.ENCRYPT` between the collection steps and `WRITE_ARCHIVE`, so a Dry Run renders it. `adapters/tar.py::write_archive(out, manifest_builder, members, *, cipher: MemberCipher | None)` — `cipher` is typed by a new port this story adds, `ports/crypto.py::MemberCipher(Protocol)`: `check() -> None`, `encrypt(reader: IO[bytes], writer: IO[bytes]) -> None`, `decrypt(reader: IO[bytes], writer: IO[bytes]) -> None` — no `bytes` in any signature (AD-21); E002-S02-007 places it on the port-split allowance and Epic 4's `adapters/crypto.AgeMemberCipher` implements it. Until Epic 4 lands, every composition root binds `cipher=None`. With a cipher, each payload member is streamed through `cipher.encrypt(reader, writer)` into its own file in the Run workspace and hashed (SHA-256 and size over the ciphertext as stored) as it is written; `ManifestMember.encrypted` is `True` for every payload member; `manifest.json` is never passed through the cipher. Because `manifest.json` must be the first member (AD-23) and `age` ciphertext is not reproducible, a member cannot be encrypted twice (once to hash, once to write): every payload member's ciphertext is staged before the Manifest is written, then the Manifest and the staged files are written in order, each staged file deleted as soon as it has been copied into the tar. **Workspace disk use on the encrypted path is therefore bounded by the total ciphertext (about the Archive's size), not by the largest member**; memory stays bounded (AD-21 — every copy is a fixed-size chunked stream). This bound is stated in `write_archive`'s docstring and in the operator docs for `--recipient`. With `cipher=None` the unencrypted path is unchanged.
- **A second Site Descriptor constructor, for a target with no `wp-config.php` (AD-3; E003-S01-001).** `adapters/database.py::site_descriptor_from_archive_config(site_root: Path, config_file: Path) -> tuple[SiteDescriptor, CredentialSource]`: `config_file` is the Archive's `wp-config.php` member already extracted by `extract_archive(..., roles={MemberRole.CONFIG})` (v1) or, for a v0 Archive (whose view has `config_path is None`), the `site-root`-role member named `wp-config.php` into the Run workspace; `site_root` is the **target's** canonical Site Root, so the descriptor points at the target, not at where the Archive was taken. It reads `config_file` through the same `WpConfigFile` path as `site_descriptor_from_wp_config` (one parsing path, two entry points; both live in `adapters/database.py`, so the "one construction site" rule above still names one module). The workspace copy is removed with the workspace.
- **Restore-facing error classes raised by Epic 2's modules (AD-14; E003-S02-004).** Added to `domain/errors.py`: `RefusedError(BackupError)` — the base every refusal derives from (E002-S02-006 maps it to `REFUSED`); `AdminCredentialsRequiredError(CredentialsError)` with `flags: tuple[str, ...]`; `DatabaseRefusedError(RefusedError)` wrapping `l3io.wp.database.RefusedError`, carrying the verdict's finding codes as `findings: tuple[str, ...]` (codes only, never messages that might quote a value); `ProvisioningFailedError(BackupError)` wrapping database's `ProvisioningError`, carrying which flags of the partial result had been applied (`completed: tuple[str, ...]`); `ConfigWriteFailedError(BackupError)` with `path`, `key`, `reason` (never the value), raised by `adapters/config_writer`. **Classes whose only raise site is a later epic's own module are defined in that module** as `BackupError` subclasses (the precedent `core/exclusions` and `adapters/crypto` already follow); the walked hierarchy test and E002-S02-006's mapping test cover them without an edit here.

### Error and edge case handling

- `--wp-dir` missing, not a directory, or without a readable `wp-config.php`: `InvalidSiteDescriptorError` / a `ConfigUnreadableError` from database re-raised as `CredentialsError` — nothing written, no workspace left behind.
- `wp-config.php` defines `DB_USER` but not `DB_PASSWORD` (or the reverse): database raises `CredentialsUnobtainableError` (a failure, not an absence); re-raised as `CredentialsError` naming the source label and the missing key, never the value.
- Database unreachable or authentication refused: database's `DatabaseUnreachableError` / `AuthenticationFailedError` re-raised as `DatabaseUnreachableError` / `CredentialsError` with `raise ... from`; no partial Archive at the final name; workspace removed.
- `mysqldump` absent or killed mid-stream: database raises `TransferError`; re-raised as `DumpFailedError`; the staged Archive is discarded.
- Destination directory missing, unwritable, or full (`ENOSPC`) mid-write: `ArchiveWriteError` naming the path; temporary file removed; final name absent.
- Final name already exists: refused with `ArchiveWriteError(reason="exists")` before any dump is taken.
- A Site Root file vanishing or changing size between hashing and writing: the backup fails naming the member; it is never silently skipped or published with a stale checksum.
- Symlinks inside the Site Root are stored as symlink members, never followed; a symlink pointing outside the Site Root is stored as a link, not as the target's content. Special files (sockets, FIFOs, devices) are skipped and recorded in the run's log.
- Empty Site Root apart from `wp-config.php`, and an empty database: both produce a valid Archive (boundary).
- The `l3io-wordpress-database` extra not installed: `MissingExtraError(extra="database")` naming the extra to install, raised before any write.

- *(Added 2026-10-20.)* A Manifest whose `origin.kind` is a value this build does not know: read as `origin=None` plus a WARNING naming the value — the Archive stays readable (forward compatibility); a malformed `origin` (not an object, missing `run_id`) fails `UNREADABLE` like any malformed Manifest field.
- A cipher that raises mid-member: the staged ciphertext and the staged Archive are discarded, the error propagates as the cipher's own `BackupError` subclass (or `ArchiveWriteError` for an `OSError`), and nothing reaches the final name.
- An `ExclusionPolicy` that raises: the backup fails naming the path being decided; it is never treated as "include".
- `site_descriptor_from_archive_config` against an Archive with no config member (a `database`-scope Archive, or a v0 Archive whose `wp-root/` lacks `wp-config.php`): `InvalidSiteDescriptorError(reason="archive has no wp-config.php")`, nothing written outside the workspace.

### Security considerations

- Credentials are resolved only by database's `WpConfigFile.resolve()` inside `adapters/database.py`, passed straight to `dump`, and never stored on the Site Descriptor, in the Manifest, in a log record, or in an exception message. The Manifest's `source` projection is asserted credential-free by a test that plants a known password and searches the Manifest bytes for it.
- `repr(SiteDescriptor)` contains no credential (it holds none); a test asserts it. The full no-credential-anywhere assertion across a backup is E002-S02-004's (AG-14) and runs against this path.
- The Dump lives only in the `0700` Run workspace, written `0600` by database; the staged Archive is created `0600`; the published Archive keeps `0600` (it contains the whole database — PRD §7.2).
- `MYSQL_PWD` is never set; no argument vector or option file is built here (ADR-0015).
- Site Root traversal never follows a symlink out of the tree (see Error handling); member paths come only from `member_path`, which rejects escaping paths.

- *(Added 2026-10-20.)* `ManifestOrigin` and `ManifestExclusions` carry no credential, recipient, identity or passphrase; the existing planted-password Manifest test is extended to a Manifest with both keys set, and to an encrypted Archive (asserting the Manifest names no recipient and no key material — ADR-0014).

### Testability approach

- **Unit (pure, no I/O):** `tests/unit/domain/test_site.py` (frozen, no setter, construction-time errors, repr), `tests/unit/domain/test_archive_format.py` (`member_path` rejects `..`, absolute, NUL, backslash; Manifest JSON round-trip; unknown keys ignored; no KDF/key field exists), `tests/unit/domain/test_storage_target.py` (bare path, `file://`, `s3://` → `UnsupportedStorageSchemeError`), `tests/unit/core/test_backup_plan.py` (step order). `tests/unit/` is new; it mirrors the package layer directories and needs no conftest beyond pytest's `tmp_path`.
- **Adapter contract tests:** `tests/adapters/test_tar_writer.py` (first member is `manifest.json`; gzip; checksum equals SHA-256 of the stored member; changing a file between passes fails), `tests/adapters/test_local_store.py` (failed write leaves no final name; existing final name refused; `os.replace` happens only after the verifier passes — asserted with a verifier double that fails), `tests/adapters/test_workspace.py` (mode `0700`; removed on success and on an exception).
- **Integration (marked `@pytest.mark.integration`, the existing marker):** `tests/integration/test_backup_end_to_end.py` against the CI MySQL 8.4 / MariaDB 11.4 service and `tests/data/wp-config.php`: one Archive produced; members are `manifest.json`, `dump/…`, `site-root/…`; mtimes, a checksum of the database (`CHECKSUM TABLE` over every table) and `wp-config.php` bytes are identical before and after.
- **AD-21 (AG-13):** this story adds the first `ports/` module, which trips `tests/contracts/test_streaming.py::test_the_real_streaming_bound_is_still_owed`. That tripwire is **replaced**, as its own docstring directs, by a test that drives the real backup path against a site whose Site Root and Dump total at least 10× `RSS_BOUND_BYTES` and asserts peak RSS stays under the bound, keeping the existing two-way calibration. A second contract test walks every Protocol in `ports/` with `typing.get_type_hints` and fails if any parameter or return annotation is `bytes` — scope derived from the `ports/` package, not a list.
- **AD-11 tripwire:** adding `adapters/tar.py` trips `tests/contracts/test_extraction.py::test_the_real_containment_test_is_still_owed`. This story retargets that tripwire from "any adapter module exists" to "`adapters/tar.py` defines no `extract_archive`", so it still fires on the event it stands for; E002-S01-003 replaces it with the real containment test. The narrowing is stated in the test's docstring.
- **AD-14:** `tests/contracts/test_exception_hierarchy.py` imports every module under `src/l3io/wp/backup/`, collects every `Exception` subclass defined there, and asserts each derives from `BackupError` — scope derived by walking the package.
- **AD-6 single owner:** the literal grep described under Interface contracts, in `tests/contracts/test_archive_format_owner.py`.

- *(Added 2026-10-20.)* `tests/unit/domain/test_archive_format.py` gains: `origin` and `exclusions` round-trip; a Manifest without them serialises byte-identically to one built before this addition (golden string); an unknown `origin.kind` reads as `None`.

### Existing-library check
