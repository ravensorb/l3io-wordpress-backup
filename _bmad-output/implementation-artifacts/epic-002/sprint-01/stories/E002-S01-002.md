# E002-S01-002: Choose what the backup covers


**Implements:** FR-2


As an operator,
I want to back up only the files or only the database,
So that I can take a fast partial backup when that is all I need.

**Acceptance Criteria:**

**Given** the Backup Scope values `files`, `database` and `all` (PRD Glossary, FR-2), accepted on the frozen CLI as `--mode files|db|all` (AD-22)
**When** each one is passed
**Then** the behaviour matches the name, and no accepted value silently falls through to another
**And** the CLI value `db` maps to the domain value `database` in exactly one place in `cli/`, and the domain never spells it `db`
**And** `database` produces a complete Archive containing a Dump and a Manifest and no Site Root members, never a loose dump file and no Archive
**And** `files` produces an Archive whose Manifest records that no Dump is present

## Business acceptance criteria

### Outcome

An operator passes `--mode files`, `--mode db` or `--mode all` to `wpbackup2 backup` (a library caller passes `BackupScope.FILES`, `.DATABASE` or `.ALL`) and gets exactly that: `files` yields an Archive with Site Root members and a Manifest recording `dump_present: false`; `db` yields a complete, verifiable Archive with a Dump and a Manifest and no `site-root/` member — never a loose `.sql` file; `all` yields both. Omitting `--mode` means `all` (the v0.2.21 default, preserved), and the v0.2.21 defect where `--mode db` silently backed up everything is gone. A reviewer can confirm each by listing the Archive's members and reading its Manifest.

### Non-goals

- Exclusions within the Site Root (FR-5) — Epic 4.
- Restoring a `files`-scope Archive without claiming a database restore — that is FR-2's restore-side consequence and belongs to Epic 3 (story 3.1); this story only guarantees the Manifest records the absence.
- Restore Mode and AD-25's flag table — restore's `--mode` and `--cleanfirst`/`--force` mapping are Epic 3's (story 3.2); this story touches only the backup subcommand's `--mode`.
- Adding `files`, `database` or `all` aliases, or any new spelling: the accepted CLI set stays exactly `{files, db, all}`.
- Changing the Archive format or the backup pipeline — those are E002-S01-001's; this story only selects which steps run.

## Technical acceptance criteria

### Interface contracts

- **`domain/backup_scope.py`** (created by E002-S01-001 with `ALL` only; completed here): `class BackupScope(StrEnum): FILES = "files"; DATABASE = "database"; ALL = "all"`, with the Glossary values verbatim. Pure, `__all__` declared, module docstring cites FR-2 and the PRD §4 Glossary. The domain never spells a value `db`: a contract test greps `src/l3io/wp/backup/{domain,core,ports,adapters,api}` for the string literal `"db"` and fails on a hit.
- **One CLI→domain mapping, in `cli/`** (decision 5 of 2026-10-20; triage E-12): `cli/scope.py` declares `CLI_MODE_TO_SCOPE: Final[Mapping[str, BackupScope]] = MappingProxyType({"files": BackupScope.FILES, "db": BackupScope.DATABASE, "all": BackupScope.ALL})` and `backup_scope_from_cli(value: str) -> BackupScope`, which indexes the mapping with no `.get` default and no fallback branch. No other module translates `db`. Sibling convention, from `domain/flag_map.py`: an immutable `MappingProxyType` table typed `Final`, with a contract test deriving its scope from the parser.
- **`cli/parser.py`**: the backup subparser's `--mode` is `choices=["files", "db", "all"], default="all"`, spelled and defaulted exactly as v0.2.21 (AD-22). It lives on the backup subparser, or on a shared parent that the restore subparser also uses; if shared, AD-25's existing `tests/contracts/test_flag_map.py` will then derive `mode` as a restore dimension, and this story must leave that test green — so `--mode` is added to the backup subparser only, and Epic 3 adds restore's own `--mode` with its flag-map entries.
- **`core/backup.py`**: `build_backup_plan(site, scope: BackupScope, target)` — `scope` is a required parameter with **no default**, and `BackupScope` is in `tools/check_mode_defaults.py`'s guarded set (AD-5 names it), which this story confirms by planting a defaulted `scope: BackupScope = BackupScope.ALL` in a throwaway file under the test's tmp tree and asserting the tool reports it. Plan steps per scope: `FILES` → `COLLECT_SITE_ROOT, WRITE_ARCHIVE, VERIFY, PUBLISH`; `DATABASE` → `DUMP, WRITE_ARCHIVE, VERIFY, PUBLISH`; `ALL` → all five. The mapping from scope to steps is a `match` over `BackupScope` with `typing.assert_never` in the fall-through, so mypy `--strict` rejects an unhandled value.
- **Manifest**: `Manifest.backup_scope` carries the domain value (`"database"`, never `"db"`); `dump_present` is `False` and `dump_sha256` is `None` for `FILES`; a `DATABASE` Archive's `members` contains no `site-root`-role entry.
- **`classification`**: AG-24 asks for this story to be reclassified `standard` (it writes a Glossary-bound `domain/` enum, resolves AG-4 and touches a frozen accepted-value set). The frontmatter is not edited here, per the elaboration brief; the reclassification is the orchestrator's.

### Error and edge case handling

- `--mode` with any value outside `{files, db, all}` (including `database`, `DB`, `Files`): argparse usage error, exit `USAGE` (2) once E002-S02-006 lands — nothing read, nothing written.
- `--mode db` against a Site whose database is unreachable: fails as E002-S01-001 defines (`DatabaseUnreachableError`), with no Archive and no loose dump left anywhere — the workspace is removed in `finally`.
- `--mode files` needs no database access: it neither resolves credentials nor connects. A Site whose database is down still backs up its files, asserted by an integration test with the database stopped. `wp-config.php` is still read for the Site Descriptor (site root and the `db_name` used in the default Archive filename).
- `--mode db` never writes the Dump outside the Run workspace and never publishes anything other than a full Archive.
- A future scope value added to `BackupScope` without a CLI token and a plan branch fails both the mapping test and mypy (see Testability).

### Observability requirements

- The resolved Backup Scope is logged once at the start of the Run as `backup_scope` with the **domain** value (`database`, not `db`), and recorded in the Manifest, so the scope performed is visible in both places (mirrors FR-6's "the mode requested is the mode performed" for restore).
- Skipped steps are not emitted as phases; only the steps in the plan produce `phase` records (E002-S01-001's per-step fields).

### Security considerations

- `--mode files` must not resolve database credentials at all — the least-privilege path takes no secret it does not need; asserted with a credential source double whose `resolve()` raises.
- Accepted values are a closed `choices` set validated by argparse before any I/O; nothing from `--mode` reaches a path, a log format string or a subprocess.

### Testability approach

- `tests/unit/domain/test_backup_scope.py`: the enum's values equal the Glossary's set `{"files", "database", "all"}` exactly.
- `tests/unit/cli/test_scope_mapping.py`: scope **derived from the parser** — read the backup subparser's `--mode` action `choices` (same introspection helper style as `tests/contracts/test_flag_map.py`) and assert `set(CLI_MODE_TO_SCOPE) == set(choices)` and that the mapping's values cover `BackupScope` exactly (bijection). A planted extra choice on a throwaway parser proves the derivation sees it.
- `tests/contracts/test_no_db_spelling.py`: the `"db"` literal grep outside `cli/`, with a scope assertion that the walked directories exist and are non-empty.
- `tests/unit/core/test_backup_plan.py`: one parametrised case per `BackupScope` member — parametrised from `list(BackupScope)`, not a hand list — asserting the exact step tuple.
- `tests/integration/test_backup_scope.py` (`@pytest.mark.integration`): for each scope, the produced Archive's member roles and Manifest (`backup_scope`, `dump_present`); for `database`, no `site-root/` member and nothing left in the working directory or workspace except the published Archive; for `files`, run with the database service stopped.

### Existing-library check

stdlib `enum.StrEnum`, `types.MappingProxyType` and `argparse` `choices` cover everything here; no library is warranted and none is added. Plan dispatch uses `typing.assert_never` for exhaustiveness rather than a hand-written check.
