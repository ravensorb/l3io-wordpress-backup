# E004-S01-001: Exclude paths that should not be in a backup


**Implements:** FR-5


As an operator,
I want caches and logs left out of my archive,
So that backups stay small and restores do not resurrect stale state.

**Acceptance Criteria:**

**Given** a documented default exclusion set
**When** a backup runs
**Then** the set is enumerable at runtime and overridable
**And** an excluded path is absent from the Archive and recorded as excluded in the Manifest
**And** `wp-config.php` is never excluded, by any rule

## Business acceptance criteria

### Outcome

A `wpbackup2 backup` of a Site whose Site Root holds `wp-content/cache/` and `wp-content/debug.log` produces an Archive that contains neither, while every other file — `wp-content/uploads/`, plugins, themes and `wp-config.php` — is present. The Archive's Manifest lists the active exclusion patterns and each excluded path with the pattern that excluded it, so an operator reading the Manifest can see what was left out and why. The default exclusion set is a named constant, documented, printable at runtime, and replaceable or extendable by the operator. No pattern, default or custom, can remove `wp-config.php` from an Archive. A reviewer can tell it happened by listing the Archive's members and reading its Manifest after a backup of a Site seeded with a cache directory, a log and a deliberately hostile pattern such as `*`.

### Non-goals

- Excluding database tables or rows — exclusions apply to paths within the Site Root only. Selective database content is not in v1.
- Exclusions for the `config`-role member (a `wp-config.php` outside the Site Root, FR-29): it is not under the Site Root and no exclusion rule is evaluated against it.
- Restore-side filtering. A restore restores what the Archive holds; this story only decides what a backup writes.
- Reading exclusions from a file in the Site Root (a `.wpbackupignore`). Patterns arrive through the API and CLI only.
- The Site Root traversal itself, the Manifest schema, the CLI parser and the backup composition root — all Epic 2's (`adapters/tar`, `domain/archive_format`, `cli/*`, `core/backup`). This story supplies the pure decision they consult; see the `OPEN:` under Interface contracts.

## Technical acceptance criteria

### Interface contracts

Files this story adds, following the conventions the existing siblings and E002-S01-001 set: module docstring naming the AD it carries, `from __future__ import annotations`, an explicit `__all__` (as `core/__init__.py` and `domain/flag_map.py` do), no new `__init__.py`, and — because it is under `core/` — inside `tools/check_purity.py`'s walked scope and the import-linter `forbidden`/`layers` contracts (AD-1): it imports `domain/` and `pathspec` only.

- **`src/l3io/wp/backup/core/exclusions.py` (new; Epic 4 owns `core/exclusions`).**
  - `DEFAULT_EXCLUSIONS: Final[tuple[str, ...]]` — gitignore-syntax patterns, anchored at the Site Root. This story fixes the list as `("wp-content/cache/", "wp-content/upgrade/", "wp-content/upgrade-temp-backup/", "wp-content/debug.log")` — object/page caches, core's update scratch directories and WordPress's own debug log. It answers the PRD's `[NOTE FOR PM]` by being conservative: nothing under `wp-content/uploads/`, `wp-content/plugins/` or `wp-content/themes/` is matched, asserted by test. Changing the list is a reviewed change to this constant and its documentation, not a builder's choice.
  - `PROTECTED_PATHS: Final[frozenset[str]] = frozenset({"wp-config.php"})` — Site-Root-relative POSIX paths no rule may exclude.
  - Frozen `ExclusionSet(patterns: tuple[str, ...], source: ExclusionSource)` with `class ExclusionSource(StrEnum): DEFAULT = "default"; CUSTOM = "custom"; NONE = "none"`. Constructors: `ExclusionSet.default()`, `ExclusionSet.none()`, `ExclusionSet.from_patterns(patterns: Sequence[str], *, include_defaults: bool) -> ExclusionSet` (defaults first, then the operator's patterns, so a later `!pattern` can re-include a default). Patterns are compiled once with `pathspec.GitIgnoreSpec.from_lines` at construction; an empty or whitespace-only pattern, or one `pathspec` rejects, raises `InvalidExclusionPatternError(pattern: str, reason: str)` — a `BackupError` subclass defined in this module (AD-14; caught by E002-S01-001's walked hierarchy test).
  - `ExclusionSet.decide(relative: PurePosixPath, *, is_dir: bool) -> ExclusionDecision`, pure, where frozen `ExclusionDecision(excluded: bool, pattern: str | None, protected: bool)`. A directory decision of `excluded=True` means the traversal prunes the whole subtree without descending. `relative` must be relative, non-empty and contain no `..`; anything else raises `ValueError` (a programming error, not operator input).
  - Frozen `ExcludedEntry(path: str, pattern: str, is_dir: bool)` — the value Epic 2's Manifest records per excluded path (top-most pruned path only; a pruned directory's contents are not listed individually).
  - `enumerate_defaults() -> tuple[str, ...]` returns `DEFAULT_EXCLUSIONS` — the runtime-enumerable surface the CLI and `api/` expose.
- **`pyproject.toml`**: `pathspec>=1.1,<2` added to `[project] dependencies` (FR-26 upper bound; 1.1.1 is already in `uv.lock` as a dev transitive of mypy/hatchling, licence MPL-2.0, no runtime dependencies of its own, ships `py.typed`). The dependency inventory records its licence and why it is present.
- **`docs/exclusions.md` (new)**: the documented default set, as a table between generated-content markers, plus the protection rule and the pattern syntax (gitignore semantics, Site-Root-anchored).
- **Consumers (Epic 2's modules, not edited here).** The Site Root traversal calls `decide()` once per entry before descending; the Manifest gains `exclusions: {"source": ..., "patterns": [...], "excluded": [{"path", "pattern", "is_dir"}, ...]}`; the CLI gains repeatable `--exclude PATTERN`, `--no-default-excludes` and a way to print `enumerate_defaults()`; the plan/Dry Run output names the active set. Manifest reads already ignore unknown keys, so the new key is forward-compatible.

### Error and edge case handling

- **`wp-config.php` under any rule**: `decide(PurePosixPath("wp-config.php"), is_dir=False)` returns `excluded=False, protected=True` for every pattern set, including `*`, `**`, `*.php`, `/wp-config.php`, `wp-config.php` and a pattern list that negates and re-adds it. When an operator-supplied pattern would have matched it, a single WARNING names that pattern; the backup proceeds with `wp-config.php` included. It is not an error, because a broad pattern such as `*.php` legitimately matches other files.
- **A directory pattern matching an ancestor of a protected path**: not reachable in the default layout (`wp-config.php` sits at the Site Root, which is never itself a candidate). If `PROTECTED_PATHS` ever gains a nested path, `decide()` refuses to prune any ancestor directory of a protected path (returns `excluded=False` with `protected=True`); a unit test covers this with a nested protected path built in the test.
- **Root-level and empty inputs**: the Site Root itself is never passed to `decide()`; `PurePosixPath("")`, `"."`, an absolute path or a `..` segment raises `ValueError`.
- **Patterns**: an empty string, whitespace only, or a pattern `pathspec` rejects raises `InvalidExclusionPatternError` at `ExclusionSet` construction — before any dump or file read. Mapped to the existing `ExitCode.USAGE` through Epic 2's `cli/exit.py::exit_code_for` (no new code; part of the OPEN above).
- **Case and separators**: matching is case-sensitive and POSIX-separated, matching the filesystem the Site Root lives on; a Windows-style `wp-content\cache` pattern is matched literally (and matches nothing), not translated.
- **Symlinks**: matched by the link's own path within the Site Root, never by its target; excluding a symlink excludes the link member only.
- **`--mode db` (`BackupScope.DATABASE`)**: no Site Root is collected, so no decision is made; the Manifest records the active set with an empty `excluded` list rather than omitting the key.
- **Every file excluded**: allowed; the Archive still carries `wp-config.php` and is valid (E002-S01-001's empty-site boundary case).
- **Large match counts**: only top-most pruned paths are recorded, so a pruned directory costs one entry however many files it holds. A Site with 50,000 individually matched files (e.g. `*.log` across plugins) produces a Manifest that stays under E002-S01-003's Manifest size cap — asserted by test; if a pattern set ever produced a Manifest over the cap, the backup fails before publishing rather than publishing an Archive its own verifier rejects.

### Observability requirements

- `core/exclusions` is pure and logs nothing itself (AD-1 forbids `structlog` there). The consumer logs from the decisions it returns, through Epic 2's Run-bound logger (`run_id` via contextvars, AD-10): one INFO `exclusions_applied` per Run with `source`, `pattern_count`, `excluded_count`; one DEBUG `path_excluded` per top-most excluded path with `path` and `pattern`; one WARNING `protected_path_kept` with `path` and `pattern` when a pattern would have matched `wp-config.php`. Field names follow E002-S02-005's log schema.
- The active pattern list is printed in Dry Run output, so an operator can see what would be left out before a real Run (AD-4: the decision is pure, so a Dry Run computes it for real).
- Path strings reaching logs are passed through `repr()`-style escaping as E002-S01-003 requires for member names.

### Security considerations

- Exclusion only subtracts: no pattern, including a negation, can add a path outside the Site Root to an Archive, because `decide()` is only ever asked about entries the traversal already found inside it. Patterns are matched as strings; none is passed to a shell, `glob` or the filesystem.
- `wp-config.php` protection is a safety property, not a convenience: an Archive without it cannot be restored to a working Site, so a hostile or careless pattern must not be able to remove it.
- Excluded path names are recorded in the plaintext Manifest, extending the deliberate trade ADR-0014 already accepts for member names (names and sizes visible to whoever holds the Archive). No file content is recorded for an excluded path.
- `pathspec` is a pure-Python, dependency-free string matcher; its tree-walking helpers (`match_tree*`, `check_tree_files`) do I/O and are not used — a test greps `core/exclusions.py` for them.

### Testability approach

Test layout follows E002-S01-001's convention: `tests/unit/` mirrors the package layer directories; contract tests live in `tests/contracts/`; the live-database tier carries the existing `@pytest.mark.integration` marker.

- `tests/unit/core/test_exclusions.py` (pure, no filesystem): each default pattern excludes its intended path and nothing under `wp-content/uploads/`, `wp-content/plugins/` or `wp-content/themes/` (fixed sample paths per directory); directory patterns return `is_dir`-pruning decisions; `!` negation re-includes a default; invalid patterns raise `InvalidExclusionPatternError`; `ValueError` for absolute, empty and `..` inputs; `ExclusionSet` is frozen.
- `tests/contracts/test_wp_config_never_excluded.py`: a hostile pattern table (`*`, `**`, `**/*`, `*.php`, `wp-config.*`, `/wp-config.php`, `wp-config.php`, `!wp-config.php` followed by `wp-config.php`) **plus every pattern in `DEFAULT_EXCLUSIONS`**, each alone and all combined, asserts `decide("wp-config.php")` is never excluded. A second case iterates `PROTECTED_PATHS` rather than naming `wp-config.php`, so the guard's scope is derived from the constant; a planted nested protected path proves ancestor-pruning is refused.
- `tests/contracts/test_exclusions_documented.py`: parses the generated table in `docs/exclusions.md` and asserts it equals `DEFAULT_EXCLUSIONS` in order — the documentation cannot drift from the constant.
- `tests/contracts/test_exclusions_pure.py`: AST scan of `core/exclusions.py` rejecting any reference to `pathspec`'s tree-walking APIs (covered beyond `tools/check_purity.py`, which cannot see into `pathspec`).
- End to end (blocked on the OPEN seams): `tests/integration/test_backup_exclusions.py` builds a Site Root in `tmp_path` with `wp-content/cache/x`, `wp-content/debug.log`, `wp-content/uploads/a.jpg` and `wp-config.php`, runs a `--mode files` backup with defaults plus `--exclude '*'`, and asserts: `uploads/a.jpg` absent only in the `*` run, `wp-config.php` present in both, cache and log absent in both, and the Manifest's `exclusions.excluded` lists exactly the pruned paths with their patterns. Unmarked if a files-only backup needs no live database; otherwise `@pytest.mark.integration`.
- The 50,000-match Manifest size case runs against `ExcludedEntry` serialisation through Epic 2's `manifest_to_json`, not a real tree.

### Existing-library check

Pattern matching is gitignore-style glob matching, a domain the global rules forbid hand-rolling. `pathspec` 1.1.1 (`GitIgnoreSpec`) covers it: gitignore semantics including anchoring, directory-only patterns, `**` and negation; pure Python; MPL-2.0; already resolved in `uv.lock`. The stdlib alternatives were checked and rejected: `fnmatch`'s `*` crosses `/`, so `wp-content/*.log` would match nested paths, and it has no directory-only or negation semantics; `PurePath.full_match` (recursive `**`) exists only from Python 3.13 while `requires-python = ">=3.11"`; `PurePath.match` matches from the right and cannot anchor. No custom matcher is written.
