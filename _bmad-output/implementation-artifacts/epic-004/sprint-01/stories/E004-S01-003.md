# E004-S01-003: Encrypt an archive at rest


**Implements:** FR-4


As an operator,
I want my archive encrypted,
So that a file containing every user record is not readable by whoever finds it.

**Acceptance Criteria:**

**Given** encryption configured with `age` recipients, or with a passphrase
**When** a backup runs with encryption
**Then** each payload member is `age`, encrypted through `l3io-wp-database`, and the Archive yields no plaintext database or file content to an inspector without the key (ADR-0014)
**And** any encrypted member decrypts with the stock `age -d`, without this package
**And** the Manifest records which members are encrypted and carries no key material
**And** a wrong key or passphrase raises a distinct named error, not a generic corruption error
**And** no key or passphrase appears in process arguments, logs or exceptions
**And** the passphrase resolution chain is shared verbatim by the CLI and the library (AD-26)
**And** recipient/identity encryption builds on database v0.1.0; the passphrase path lands with database **0.2.0** (`passphrase=`), and until then a passphrase-only configuration is refused naming that release

## Business acceptance criteria

### Outcome

`wpbackup2 backup --wp-dir <Site Root> --recipient age1…` produces an Archive in which `manifest.json` is plaintext and every payload member is encrypted. That covers the Dump and every `site-root/…` and `config` file. Each encrypted member is a standard `age` file, so an operator with the matching identity recovers any member with the stock `age -d -i key.txt`, without this package installed. Someone holding the Archive but no key can still identify, version-gate and checksum-verify it, because the Manifest marks each member `encrypted: true` and its checksum covers the ciphertext. They cannot read any database row or file content from it. Decrypting with the wrong identity raises a named decryption error that is distinct from a corrupt-Archive error and maps to a different exit code. The key never appears in an argument vector, a log record or an exception. Recipient and identity encryption works on `l3io-wordpress-database` v0.1.0. Passphrase encryption works once database **0.2.0** ships; until then, a passphrase-only configuration is refused before anything is read, with a message naming that release. A reviewer can tell it happened by backing up a Site seeded with sentinel strings, grepping the decompressed Archive for them (none found), and decrypting one member with `age -d`.

### Non-goals

- Restoring from an encrypted Archive onto a Site. That is Epic 3 story 3.1, which calls this story's decryption adapter. The Safety Snapshot's encryption (FR-8, AD-26's "no silent plaintext Snapshot" default) is Epic 3 story 3.3.
- Implementing the AD-26 passphrase resolution chain or the CLI flags. Both live in Epic 2's `cli/` (Epic List ownership note). This story consumes the chain and does not redefine it. See the `OPEN:` under Interface contracts.
- Hiding member names, sizes or the source Site identity. The plaintext Manifest exposes them by design (ADR-0014, "Kept from ADR-0006"), and an operator who needs them hidden encrypts at the storage layer as well.
- Key management: generating, rotating, escrowing or recovering keys. Losing every identity or the passphrase loses the Archive, and the documentation says so plainly.
- Verifying plaintext integrity with a key (a "deep verify"). Verification stays keyless, over ciphertext (E002-S01-003).
- Having `adapters/database` call `dump(..., recipients=)` so a plaintext Dump never lands in the Run workspace. That optimisation belongs to Epic 2's module. This story encrypts the Dump member like every other member, and the plaintext Dump stays confined to the owner-only workspace AD-12 already removes.
- Any cipher, KDF or `age` implementation in this package.

## Technical acceptance criteria

### Interface contracts

Files this story adds or changes follow E002-S01-001's conventions: a module docstring naming the AD and ADR it carries, `from __future__ import annotations`, an explicit `__all__`, and no new `__init__.py`. `adapters/` may import `domain/`, `ports/` and `core/` (import-linter `layers`). Optional dependencies are imported **inside the function that uses them** (AD-8), as `adapters/database.py` does.

- **`src/l3io/wp/backup/adapters/crypto.py` (new; Epic 4 owns `adapters/crypto`). It is a thin adapter over `l3io.wp.database.encryption`. Signatures were verified at tag `v0.1.0`: `encrypt(reader: IO[bytes], writer: IO[bytes], recipients: Sequence[str]) -> None`, `decrypt(reader: IO[bytes], writer: IO[bytes], identities: Sequence[str]) -> None`, `check_recipients(recipients: Sequence[str]) -> None`, and `read_identity(path: str | Path, passphrase: str | None = None) -> str`. In v0.1.0 these are importable from the public module `l3io.wp.database.encryption`, not the package root. From 0.2.0 they are imported from the root, per database plan 4's handoff note.**
  - Frozen `AgeRecipients(recipients: tuple[str, ...])` and `AgeIdentities(identities: tuple[str, ...])`. Each `__repr__` shows only the count (`AgeIdentities(<2 identities>)`), so an identity can never be `repr`ed into a log (AD-7, AG-14).
  - `class AgeMemberCipher` with `__init__(self, *, recipients: AgeRecipients | None = None, identities: AgeIdentities | None = None, passphrase: str | None = None)` and three methods:
    - `check(self) -> None` validates before any data moves. With recipients it calls `check_recipients`. With a passphrase on 0.2.0 it calls `check_passphrase`.
    - `encrypt(self, reader: IO[bytes], writer: IO[bytes]) -> None`
    - `decrypt(self, reader: IO[bytes], writer: IO[bytes]) -> None`
  - **No method accepts or returns `bytes`** (AD-21, AG-13).
  - `passphrase_supported() -> bool` is capability detection: `"passphrase" in inspect.signature(encryption.encrypt).parameters`. No version string is parsed or compared.
  - Construction with only `passphrase=` while `passphrase_supported()` is False raises `PassphraseEncryptionUnavailableError`, naming "l3io-wordpress-database 0.2.0" and the installed version, read from `importlib.metadata.version`. It is raised from the configuration step, before preflight, dump or any write.
  - Construction with both `recipients` and `passphrase`, or with neither when encryption is requested, raises `EncryptionConfigError`. These are mutually exclusive, matching database 0.2.0's own rule.
  - **Passphrase path (lands with database 0.2.0; written against plan 4 Part B).** `encrypt(reader, writer, *, passphrase=...)` and `decrypt(reader, writer, *, passphrase=...)` emit and consume a sole scrypt recipient that stock `age -d` reads. When 0.2.0 is pinned, `passphrase_supported()` becomes True and the refusal path becomes unreachable. A test (below) fails if the refusal outlives the capability.
  - Every secret this adapter is handed is registered with the Run's `SecretRegistry` (E002-S02-004) at construction: each identity string, and the passphrase. That is the extension point E002-S02-004 reserved for this story ("the redaction set below is extensible so that story adds the passphrase without a second implementation").
- **Errors (AD-14), defined in `adapters/crypto.py` as `BackupError` subclasses** (E002-S01-001's walked hierarchy test covers them). Each wraps database's exception with `raise … from`, and none carries a key, passphrase or identity in its message or attributes:
  - `ArchiveDecryptionError(CredentialsError)`, with fields `member: str` and `reason: Literal["wrong_key", "no_key"]`, is raised from database's `DecryptionError` or when an encrypted member is read with no key. Because it subclasses `CredentialsError`, it maps to `ExitCode.CREDENTIALS` (4) through Epic 2's existing arm.
  - `EncryptedMemberCorruptError(BackupError)`, with field `member: str`, is raised from database's `CorruptDumpError` (truncated, damaged or not `age`). Its mapping is `ExitCode.VERIFICATION_FAILED` (8), as E002-S02-006's docstring records.
  - `PassphraseEncryptionUnavailableError(MissingExtraError)`, with `extra="database"`, `required="0.2.0"` and `found`, maps to `NOT_READY` (7) through the existing `MissingExtraError` arm.
  - `EncryptionConfigError(BackupError)` maps to `USAGE` (2).
  - Database's `MissingDependencyError(extra="encryption")` (pyrage absent) is re-raised as `MissingExtraError(extra="database")` with a message naming `l3io-wordpress-database[encryption]`.
  - No new `ExitCode` member is needed.
- **`pyproject.toml`**: the `database` extra becomes `l3io-wordpress-database[encryption]>=0.1.0,<0.2` (ADR-0014 Consequences). When database 0.2.0 ships, it moves to `>=0.2,<0.3`, a separate change that deletes the refusal path. This package declares no `pyrage` and no `cryptography` cipher use.
- **Manifest (AD-6, as amended by ADR-0014).** Epic 2's `ManifestMember.encrypted: bool` is set to `True` for every payload member when encryption is on. `size` and `sha256` describe the **stored ciphertext**. The Manifest records no recipient, identity, passphrase, KDF parameter, salt or algorithm field: `age` carries its own header. `manifest.json` itself is never encrypted.
- **Committed fixture (ADR-0014, "including an encrypted one").** `tests/fixtures/archives/v1/encrypted-recipient.tar.gz` is a minimal v1 Archive whose members are encrypted to a **test-only** identity committed beside it as `encrypted-recipient.identity.txt`. That file has a header comment saying it protects nothing and exists for CI. A checked-in generator reproduces the fixture, minus `age`'s random file key, so reproducibility is asserted on the Manifest's structure, not on bytes. E002-S01-003's fixture-derived supported-set test picks it up from the directory.

OPEN: the seams this story needs in Epic 2's modules are not provided by any elaborated E002 story, and Epic 4 may not edit them (decision 6):

1. A cipher Protocol in `ports/`, e.g. `ports/crypto.py::MemberCipher`, transform-only, on E002-S02-007's query/command allowance beside `ArchiveProbe`.
2. Per-member encryption in `adapters/tar.write_archive`. Each member's ciphertext is staged in the Run workspace, then hashed, then added to the tar. `age` output is non-deterministic and its size is only known after encryption, so E002-S01-001's "hash in a first pass and re-hash during the write" option is unavailable once encryption is on. Staging must be per member and removed before the next, so disk use is bounded by the largest member.
3. An `ENCRYPT` step, or an `encrypted` flag, on `core/backup.BackupPlan`, so a Dry Run reports it.
4. CLI flags in `cli/parser.py`: repeatable `--recipient`, `--recipients-file PATH`, `--identity-file PATH`, and a passphrase surface that never accepts the secret as an argument value.
5. **The AD-26 chain itself.** The Epic List assigns it to Epic 2's `cli/`, but no E002 story defines it. E002-S02-004 defers it "via Epic 4".
6. `exit_code_for` routing `EncryptedMemberCorruptError` to `VERIFICATION_FAILED` and `EncryptionConfigError` to `USAGE`, since both would otherwise fall to `FAILED`.

Until these land, `adapters/crypto` and its own tests can be delivered, but the end-to-end criteria cannot pass.

### Error and edge case handling

- **Wrong identity or passphrase**: raises `ArchiveDecryptionError(member=…, reason="wrong_key")` and exits 4. It is never `EncryptedMemberCorruptError`, never `VerificationFailedError`, and never a bare database exception.
- **Encrypted Archive read with no key**: the same error with `reason="no_key"`, raised when the first encrypted member is about to be decrypted. Keyless verification still passes, because checksums cover the ciphertext.
- **Ciphertext truncated or a byte flipped after write**: keyless verification fails first with `CHECKSUM_MISMATCH` or `TRUNCATED` (E002-S01-003). If `decrypt` is reached with a damaged stream anyway (the adapter driven directly), it raises `EncryptedMemberCorruptError` and exits 8. The two kinds stay distinct (ADR-0014).
- **Member swapped in from another Archive under the same key**: it decrypts cleanly but fails Verification with `CHECKSUM_MISMATCH`, because the Manifest's checksum is over the stored ciphertext (ADR-0014's replacement for key commitment).
- **Invalid recipient string**: `check()` refuses before the dump. Database's `InvalidArgumentsError` message includes only the first 12 characters of a recipient, which is a public key. The re-raised `EncryptionConfigError` names the recipient's index, not its text.
- **Passphrase-only configuration on database 0.1.x**: refused with `PassphraseEncryptionUnavailableError`, exit 7, before preflight. The message names `l3io-wordpress-database 0.2.0`. Nothing is read from the Site, nothing is dumped, and the workspace contains nothing.
- **Both recipients and passphrase, or encryption requested with neither**: `EncryptionConfigError`, exit 2.
- **`pyrage` not installed** (the `database` extra installed without `[encryption]`, e.g. an older lock): `MissingExtraError` naming `l3io-wordpress-database[encryption]`, raised by `check()` before any write.
- **Empty member** (a zero-byte file, an empty Dump): encrypts to a valid `age` file, has a checksum over that, and round-trips to zero bytes.
- **Symlink members** carry no content and are stored as links, unencrypted, with `encrypted: false` in the Manifest. A link target is a path and is already visible like a member name. This is asserted, so an inspector test does not flag it.
- **Broken pipe or disk full while writing ciphertext**: database re-raises `BrokenPipeError`/`OSError`. The adapter lets it propagate to Epic 2's `ArchiveWriteError` handling, so the staged file is discarded and no final name exists (AD-20).
- **Passphrase path once 0.2.0 ships**: an empty passphrase is refused by `check()` through database's `check_passphrase`, and a wrong passphrase gives `reason="wrong_key"` exactly as a wrong identity does.

### Observability requirements

- Through the Run-bound logger (`structlog.get_logger(__name__)`, `run_id` via contextvars; nothing here configures logging, AD-10):
  - one INFO `encryption_configured` per Run, with `scheme="age"`, `mode` (`"recipients"` or `"passphrase"`) and `recipient_count`;
  - E002's per-phase `WRITE_ARCHIVE` record gains `encrypted_members` and `bytes` (ciphertext bytes);
  - a decrypt failure logs ERROR `member_decryption_failed` with `member` and `reason`.
- Recipient strings are not logged, only their count. They are public keys, but logging them would turn the log into a key inventory.
- The Dry Run plan states "encrypt each payload member with age to N recipients" (AD-4). Because `check()` is a query, it runs for real, so a Dry Run with an invalid recipient refuses exactly as the real Run does.

### Security considerations

- **No secret in process arguments (FR-4, NFR-3).** This package invokes no `age` binary and builds no argument vector for encryption. The secret is passed in-process to database, which passes it to `pyrage` in-process. A passphrase or identity is never accepted as a CLI flag *value*; it arrives from a file path, the environment or a TTY prompt, per AD-26's chain.
- **No secret in logs, `repr` or exceptions (AD-7, AG-14).** Every identity and the passphrase are registered with E002-S02-004's one `SecretRegistry`, so `redact_event` scrubs any accidental occurrence. `AgeIdentities` and `AgeMemberCipher` define `__repr__` without secrets. Re-raised errors build their message from structured fields only.
- **No plaintext content in the Archive.** Every payload member with content is `age`. The only plaintext is the Manifest (names, sizes, checksums, source Site identity) and link targets: the deliberate, documented ADR-0014 trade.
- **Plaintext on disk** exists only inside the owner-only (`0700`) Run workspace (AD-12), one member at a time while it is encrypted. Ciphertext is staged there too (mode `0600`) and deleted before the next member. The workspace is removed in `finally` on both paths.
- **No key material in the Manifest**, asserted by test, including that no recipient string appears in it.
- **The committed test identity** protects only the committed fixture. A contract test asserts it is the only `AGE-SECRET-KEY-` string in the repository outside `tests/fixtures/`, so a real key committed by mistake fails CI.
- This package imports no `pyrage` and no `cryptography` cipher (ADR-0014). A contract test enforces it.

### Testability approach

Layout follows E002-S01-001: `tests/unit/` mirrors the package layers, adapter contract tests go in `tests/adapters/`, architecture guards in `tests/contracts/`, and the live-database tier uses the existing `@pytest.mark.integration` marker. Keys are generated per test with database's `generate_identity()`, except for the committed fixture.

- `tests/adapters/test_crypto.py`:
  - round-trip on an empty stream, a 1-byte stream and a multi-chunk stream;
  - a wrong identity raises `ArchiveDecryptionError(reason="wrong_key")`, with no `CorruptDumpError` reaching the caller;
  - truncation at several offsets, including inside the header, and a flipped payload byte each raise `EncryptedMemberCorruptError`;
  - an invalid recipient raises `EncryptionConfigError` from `check()`;
  - `repr()` of every public type contains no identity substring;
  - every `encrypt`/`decrypt` signature is checked by `typing.get_type_hints` to contain no `bytes` (scope: the module's public callables, found by walking `__all__`).
- **Passphrase path, against the planned 0.2.0 API**: `test_passphrase_refused_until_database_0_2` runs while `passphrase_supported()` is False and asserts exit 7 and the message naming 0.2.0. `test_passphrase_round_trip` runs when it is True, and covers stock `age -d` with the passphrase supplied through `age`'s own TTY prompt, driven via `pty`. `test_refusal_retired_with_capability` fails if `passphrase_supported()` is True and the refusal path is still reachable. Neither branch is ever silently skipped: exactly one of the first two runs on any install.
- **Stock `age -d` interoperability** (`tests/adapters/test_age_interop.py`): a member encrypted by the adapter is decrypted by the `age` binary via `subprocess` with `-i <identity file>`, and the bytes must be identical. A member encrypted by `age -r` is decrypted by the adapter. The CI test job installs the `age` package (an apt step added to the test job in `.github/workflows/ci.yml`), and the test **fails** rather than skips when `CI` is set and `age` is absent. Locally it skips with that reason.
- **Inspector** (`tests/integration/test_encrypted_backup.py`, `@pytest.mark.integration`):
  - a Site Root and database are seeded with unique sentinel strings in file bodies, in `wp-config.php` values and in a table row, and backed up with a recipient;
  - the Archive is streamed through `tarfile` and every member body is scanned, as is the raw decompressed stream. No sentinel may appear outside `manifest.json`, and `manifest.json` must contain none of the content sentinels;
  - every non-link member is `encrypted: true` and starts with `age-encryption.org/v1`;
  - `wpbackup2 verify` passes with no key;
  - one member is decrypted with stock `age -d` and must equal the source file.
- **Manifest** (`tests/unit/domain/test_manifest_no_key_material.py`, run against a Manifest built by the encrypted path): no key in the JSON object tree matches `key|kdf|salt|passphrase|identity|recipient|scrypt|nonce`. The recipient string and the identity string do not occur in its text.
- **Secrets in argv, logs and exceptions**: E002-S02-004's `credential_sentinel` fixture is extended to register the identity and passphrase as sentinels. A full encrypted backup and a failed decrypt are run, and every captured log record, exception chain and `/proc/self/cmdline` read during the Run must be clean.
- **AD-21 (AG-13) on the encrypted path**: E002-S01-001's peak-RSS test (Site plus Dump of at least 10× `RSS_BOUND_BYTES`) is parametrised to run with encryption on as well as off. Both must stay under the same bound. The parametrisation is derived from a `(encrypted: bool)` axis, not a second copy of the test.
- **AD-26 single chain** (`tests/contracts/test_single_passphrase_chain.py`): it walks every module under `src/l3io/wp/backup/`, with a scope assertion. `getpass` must be imported, and the passphrase environment-variable name must appear, in exactly one module (the chain's, once Epic 2 provides it). The CLI and `api/` roots must both resolve through that one function. It runs once the OPEN chain exists, and until then it fails naming the missing chain rather than passing over an empty set.
- **No direct crypto** (`tests/contracts/test_no_direct_crypto.py`): an AST scan of the walked package that fails on any import of `pyrage` or `cryptography.hazmat`, or any `subprocess` call naming `age`.
- **Committed key guard**: a repository scan for `AGE-SECRET-KEY-` outside `tests/fixtures/`.

### Existing-library check

Cryptography is a domain the global rules forbid hand-rolling, and ADR-0014 settles the library. `age`, via `pyrage`, is reached only through `l3io-wordpress-database`'s `encryption` module (v0.1.0 recipients and identities; 0.2.0 passphrase). Its streaming `encrypt_io`/`decrypt_io` are what make AD-21 hold on the encrypted path. ADR-0014 records why the alternatives were rejected: ADR-0006's own AES-GCM construction, a direct `pyrage` integration, the `age` CLI, and buffering whole archives for one-shot passphrase calls. Capability detection uses stdlib `inspect`, version reporting uses `importlib.metadata`, and no version comparison is hand-written. This story adds no new library; it adds the `encryption` extra of an existing one.
