**Signature drift the E003 stories must adopt** (E002's contract wins; the names are kept):
- `DatabaseQuery.survey_target` and `DatabaseCommand.ensure_database`/`load_dump`/`drop_database`/`revoke_grants` take a `DatabaseLocation` (`domain/database.py`), with the administrator and WordPress sources **bound into the adapter**, not passed per call (E002-S02-007). E003-S02-004 wrote `survey_target(site, admin)` and `ensure_database(connection, admin, wordpress)`; E003-S02-005 wrote `load_dump(..., replace=None, identities=...)` — the port has **no `replace` parameter** at all, and identities live in the bound cipher/adapter.
- `DatabaseTargetState` gains `schema_version` (E003-S02-005's post-load check needs it); `EnsureOutcome` is as E003-S02-004 wrote it.
- Database error wrappers are named `DatabaseRefusedError(RefusedError)` and `ProvisioningFailedError(BackupError)`; the config write raises `ConfigWriteFailedError`, which `adapters/staging` may wrap as its own `ConfigCutoverError`.
- E003-S02-005 must call `adapters/config_writer` (`ConfigCommand.set_constants`) instead of `l3io.wp.config.WpConfigFile` directly; a contract test (P1) allows `l3io.wp.config` imports only in `adapters/config_writer.py`.
- `--force` waives the non-empty-target refusal for exactly the parts the Mode restores; `all-clean` is `--mode all --cleanfirst --drop-database` (new flag `--drop-database`). E003-S01-002's tests read this from the table.
- Exit codes are a class attribute `BackupError.exit_code` (E002-S02-006), so a later epic's error declares an existing `ExitCode` or inherits one; nothing is added to `cli/exit.py`.
